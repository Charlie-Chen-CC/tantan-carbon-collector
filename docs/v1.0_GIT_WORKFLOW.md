## 长期同步策略

**master 是 v1.0 的稳定镜像**——两者长期保持指向同一 commit（或 master 是 v1.0 的 fast-forward 后状态）。

```
v1.0 推进 → master fast-forward 到 v1.0 HEAD
```

理由：
1. 行业惯例：master 是主分支名
2. 防 v1.0 force-push 误操作时 master 还在旧 commit
3. 用户/GitHub 链接默认走 master

## 日常开发流程

### 1. 开新功能/修复

```bash
git checkout v1.0
git pull origin v1.0
git checkout -b v1.1-fix-llm-async    # 命名规则：v1.<n>-<scope>-<short-desc>
# ... 编码 + 测试
git add -A
git commit -m "fix(llm): 异步化 ali_llm.py 阻塞调用"
git push -u origin v1.1-fix-llm-async
```

### 2. 合并回 v1.0

```bash
git checkout v1.0
git merge --no-ff v1.1-fix-llm-async -m "v1.1: 合并 LLM 异步化"
git push origin v1.0
```

### 3. 同步 master（关键！）

```bash
git checkout master
git merge --ff-only v1.0    # 只允许 fast-forward，v1.0 不能落后 master
git push origin master
```

如果 fast-forward 失败（说明 v1.0 落后 master），**不要 force push**——检查为什么 v1.0 落后。

### 4. 升版本号

```bash
# v1.0 修完一轮，准备 v1.1
git checkout v1.0
git checkout -b v1.1
git push -u origin v1.1

# v1.0 标记为稳定版（不再修改）
git tag -a v1.0.0 56bb9591 -m "v1.0.0: 06-01 重构后快照"
git push origin v1.0.0
```

## 紧急回退

### 找回 06-01 重构前的代码

```bash
git checkout backup/pre-refactor-2026-06-01
# 整个项目回到 06-01 重构前状态
# 但 GitHub 上 master/v1.0 的新 commit 不会丢
```

或者只读不改：

```bash
git show backup/pre-refactor-2026-06-01:backend/api/routes.py
```

### 撤销 v1.0 误操作

如果 v1.0 上有 commit 想撤回，但还没 push：

```bash
git reset --soft HEAD~1   # 撤销最后一次 commit，保留改动
git reset --hard HEAD~1   # 撤销最后一次 commit，丢弃改动（危险）
```

如果已经 push 到远端：

```bash
git revert <commit-hash>  # 新增一个反向 commit，不动历史
```

**不要用 `git push --force`**——会破坏 master 的同步关系。

## 已知约束

### C: 盘空间紧张

- 现状：C: 盘 2.5 GB 空闲（已清出）
- 风险：单次 git push 大于 2 GB 会失败
- 缓解：test_doc/（698 MB）和 backend/uploads/（9.2 MB）+ backend/logs/（1.1 MB）已加 .gitignore，不进 commit
- 监控：定期 `git gc --prune=now` 清松散对象

### test_doc/ 不进版本控制

```gitignore
!test_doc/.gitkeep
!test_doc/README.md
test_doc/*
!test_doc/.gitkeep
!test_doc/README.md
```

- 本地 test_doc/ 保留（开发用）
- GitHub 上 test_doc/ 目录存在但只有 .gitkeep（提示用户从 backup 分支恢复）
- 恢复方式：`git checkout backup/pre-refactor-2026-06-01 -- test_doc/`

### 大文件警告

GitHub 单文件 100 MB 上限。如果未来有大文件需求：
- 选项 A：Git LFS（需 `git lfs track *.xlsx` 配 .gitattributes）
- 选项 B：拆外部存储（S3 / OSS），git 只放元数据

当前已通过 .gitignore 规避。

### localStorage / Cookie / 密钥

- 所有 `.env` / `*.env` 不进 commit
- 前端 authStore 不再 console.log 凭证
- PBKDF2 600k（OWASP 2023）+ HttpOnly Cookie

修改这些文件时必须同步更新 `.gitignore` 和 `backend/CLAUDE.md`。

- [ ] 没误把 `backend/uploads/` 或 `backend/logs/` 暂存

- [ ] 推送后检查 `git log origin/v1.0` 确认已生效
